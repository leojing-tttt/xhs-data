# 网页控制台

在**这一台电脑**上提交一条小红书搜索，读页面自己的搜索结果，成功后下载 Excel。

这一版只有任务类型 `xhs-search`（小红书搜索）。任务记录上留着 `type`，以后要加别的类型时改 `server/task-types.js`，这一版不把没做的类型跑起来。不做抖音，不做多台电脑。

## 页面

一个页面，样式是 A3 演示层（`a3-*`，浅色，主色 `#c9677d`），不是 Ant Design。

- 关键词：必填
- 条数：必填，1 到 2000，默认 100
- 排序：综合 / 最新 / 最多点赞 / 最多评论 / 最多收藏，默认综合
- 笔记类型：不限 / 视频 / 图文 / 直播，默认不限
- 发布时间：不限 / 一天内 / 一周内 / 半年内，默认不限

没有地区，没有已看过 / 未看过。

顶部「登录」是本机占位，没有接用户中心。小红书账号要在这台电脑弹出的 Chrome 里自己登录。登录框、验证码、频控出现时任务失败，不会代填，也不会绕过。

状态只有排队、执行中、成功、失败。失败停住，不会自动重试。同一时间只跑一条。

## 筛选怎么处理

现有搜索响应钩子（与 `extensions/xhs-search-export` 同一做法，代码在那条扩展分支里）只会：

1. 打开 `https://www.xiaohongshu.com/search_result?keyword=…&source=web_user_page`
2. 记下页面自己发出的 `search/notes` 请求和响应
3. 条数不够时，复用那次请求，只推进请求里**已经有**的翻页字段：`page` / `page_num`、`cursor` / `cursor_score`、`search_id`、`refresh_type`（有该字段才改成翻页值 3）

钩子里没有排序、笔记类型、发布时间的官方参数名。这一版**不猜测参数名**，也不在本地重排或挑掉笔记来假装筛过。

所以：

- 「综合 / 不限 / 不限」表示不要额外加筛选，用页面自己的那次搜索。
- 其他选项会把任务记为失败，浏览器不会打开。

## 结果

成功时下载 Excel。工作表名「搜索结果」。列固定为：

笔记ID、标题、作者、作者ID、点赞数、笔记类型、封面图、笔记链接、作者主页

笔记 ID、作者 ID 按文本写入。点赞数缺了留空，`0` 写成 0。笔记类型里 `normal` 写成「图文」，`video` 写成「视频」。链接用响应里的笔记 id，有 `xsec_token` 就带上。不是笔记的行（例如 `rec_query`）不进入表。

扩展 1.2.2 的 `toTable` 使用同样这九个列名；它把「作者主页」放在点赞数前面，并且某一列在已捕获数据里从未出现时会整列不写。这一版按上面的顺序固定写出九列。

## 不做的事

- 不伪造搜索请求，不另造签名，不绕过登录、验证码、频控
- 不编造笔记，不按条去拉笔记详情
- 翻页间隔至少 1 秒，不并发翻页
- 不自动重试
- 服务只听 `127.0.0.1`

## 运行

需要 Node.js 22 和本机 Chrome。请用 `/usr/bin/google-chrome-stable` 这一类本体。`/usr/local/bin/google-chrome` 在这台环境里会把调试端口和用户目录钉死，不要拿它当 `CHROME_PATH`。

```bash
cd web-console
node server/index.js
```

浏览器打开 <http://127.0.0.1:8788>。

有桌面时会打开可见的 Chrome，方便自己登录。没有 `DISPLAY` 时默认无头；无头过不了登录墙。强制无头：`XHS_BROWSER_HEADLESS=1`。强制有界面：`XHS_BROWSER_HEADLESS=0`。

第一次搜索响应默认最多等 180 秒（`XHS_FIRST_RESPONSE_MS`），留给登录。下一页默认等 8 秒。进程重启时，正在执行的任务改成失败，不会接着跑。

数据在 `web-console/data/`（不提交）：任务记录、Excel、Chrome 用户目录。

## 测试

```bash
cd web-console
node --test
```

没有登录后的小红书实跑。测试用夹具响应和任务状态，不把未登录或夹具说成一次成功的线上搜索。
